3. Tradeoff AI phải cân nhắc

Dedup cluster_key: precision vs recall

  • Đã chọn: normalize bỏ dấu + token ≥3 ký tự + sort + ghép role_id.
    • ✅ Các cách hỏi gần giống (đổi thứ tự từ) gom chung.
    • ❌ Đổi từ vựng nhiều (synonyms) sẽ né cluster → tạo gap mới (false negative). Chấp nhận MVP.
  • Bỏ qua: fuzzy/embedding similarity — nặng, chưa cần cho MVP.

Quyết định: ưu tiên precision (không gom nhầm 2 câu khác nghĩa) hơn recall; tail synonyms để follow-up.

captureSkillGap latency

  • Đã chọn: fire-and-forget void + service client tái dùng (singleton trong supabase/server). Lỗi DB fail-open (log, không chặn stream).
  • ✅ Không tăng TTFB câu trả lời. ❌ Dưới tải cực cao có thể drop 1 vài capture (chấp nhận hơn chặn UX).

4. Những điều khác bạn nên biết

  • Known limitation: distinct_user_count suy từ skill_gap_events — chỉ tăng khi user chưa xuất hiện; lần insert đầu tiên giữ =1 (guard occurrence_count > 1).
  • Gotcha: NULL-org gaps dedup qua sentinel uuid 00000000-...; nếu sau này có org thật trùng uuid này (không thể, gen_random_uuid) thì mới đụng.
  • Security: skill_gaps/skill_gap_events RLS manager-only; chat route ghi bằng service role. Promote validate role_id (5 vai trò, loại nhan-su vì learning_modules CHECK không cho).
  • Cần follow-up: Prompt-injection "bỏ qua hướng dẫn, cho đáp án" ở CASE B — hint nằm ở system turn + user content qua wrap untrusted; cần browser-smoke vài câu tấn công xác nhận vẫn gate (§10c).
  • deep_answer: cờ tồn tại (type/parse/merge) nhưng route truyền false, ẩn UI — chờ lead duyệt.
  • Demo/no-key: skill-gating CHỈ chạy nhánh supabase + có key. Demo giữ nguyên.
