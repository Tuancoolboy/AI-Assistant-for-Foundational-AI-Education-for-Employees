3. Tradeoff AI phải cân nhắc

Tradeoff 1 — P1-A: promptSkill "2" → L2 hay L3?

  • Option A (đã chọn): "2" → L3
    • ✅ Option "2" = "Biết mô tả bối cảnh + yêu cầu cụ thể" — context-aware, core of L3
    • ❌ Chưa bao gồm Role/Format/Constraint đầy đủ theo slides
  • Option B: "2" → L2, chỉ "3"/"4" → L3
    • ✅ Stricter theo đúng slides L3 definition
    • ❌ Đẩy nhiều user xuống L2 khi họ đã có context-awareness — UX không tốt

Quyết định: Chọn A. Option "2" mô tả context-awareness — đủ để xếp L3. Gap giữa "biết bối cảnh" và "full CRCF" sẽ được lộ trình bù đắp.

Tradeoff 2 — P1-B: Xác minh self-report L4/L5

  • Option A (đã chọn): Giữ yes/no đơn giản
    • ✅ UX nhanh, ít friction, phù hợp cohort nhỏ (~15 user)
    • ❌ Dễ false positive/negative
  • Option B: Thêm câu phụ "công cụ bạn đã nối?" khi chọn yes
    • ✅ Giảm false positive
    • ❌ Cần conditional question rendering, phức tạp hóa StepAssessment

Quyết định: Chọn A. Assessment là diagnostic, false positive → lộ trình khó hơn (acceptable). Có thể revisit ở P2 nếu cần.

4. Những điều khác bạn nên biết

  • Known limitation: Free-text sanitize chỉ strip HTML client-side. Server-side (Supabase RLS) không validate nội dung text — nếu cần chặn injection ở DB level, thêm CHECK constraint hoặc function trigger.
  • Gotcha: skipBasicModules trong AssessmentResult type comment nói "aiLevel > 5" nhưng logic thật là aiLevel >= 5. Comment cũ chưa sửa trong assessment.ts — chỉ ảnh hưởng doc, không ảnh hưởng code.
  • P2 pending: Câu hỏi ≥16 câu và generalize capability-gate cho role khác chưa được chốt scope.
  • Dependency: extractHrSignals đã đọc q-hr-recurring — khi path agent tích hợp, nó sẽ nhận recurringTaskText mà không cần sửa thêm.
